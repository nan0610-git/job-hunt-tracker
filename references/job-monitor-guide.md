# 岗位抓取与辅助投递操作指南（Boss直聘 / 智联招聘）

本指南描述浏览器抓取岗位、辅助投递的流程与风控红线。**核心原则：模拟人类浏览节奏，最后一步（发送）必须由用户点击，绝不让账号表现为机器人。**

## 一、合规与风险声明（向用户说明用）

- Boss直聘、智联招聘用户协议均禁止自动化工具操作账号。
- 本技能采用**半自动**设计：自动筛选只是「打开页面 + 读取内容」，与人工浏览无异；点击「立即沟通/申请」前的确认与发送由用户完成。
- 若用户要求全自动投递：告知封号风险，风险自担，且不要绕过任何验证码/滑块。

## 二、抓取流程

### 1. 确认配置

先运行 `job_monitor.py config` 读取用户的筛选条件（关键词、城市、薪资下限、排除项、每日上限）。未初始化时先向用户询问各条件并 `config --init` + `--set` 写入。

### 2. 打开搜索页（使用浏览器能力，如 playwright-cli / workbuddy-browser-use）

- Boss直聘搜索 URL 格式：
  `https://www.zhipin.com/web/geek/job?query=<关键词URL编码>&city=<城市代码>`
  城市代码可先在网页上手动选一次城市，从地址栏读取；西安为 101110600（以实际地址栏为准）。
- 智联招聘搜索 URL 格式：
  `https://sou.zhaopin.com/?jl=<城市>&kw=<关键词>`
- 建议使用持久化的用户浏览器配置（带登录态），而不是新建干净会话——干净环境频繁触发登录墙与验证。
- 未登录状态 Boss 列表可见条数有限；提示用户先在浏览器中登录一次。

### 3. 解析岗位卡片 → raw_jobs.json

每个岗位卡片提取以下字段（选择器随平台改版可能变化，以实际 DOM 为准，逐卡片取文本）：

```json
{
  "platform": "zhipin",
  "title": "运维工程师",
  "company": "云启科技",
  "salary": "15-25K·14薪",
  "city": "西安",
  "url": "https://www.zhipin.com/job_detail/xxx.html",
  "tags": ["3-5年", "本科"],
  "published": "2026-10-14"
}
```

- `url` 必须是岗位详情页完整链接（辅助投递时要打开）。
- `published` 取卡片上的发布时间文本（如「今天」「3天前」），原样记录。
- 列表只抓前 1-2 页（每页约 30 条），**不要无限翻页**——翻页过深是典型机器人行为。

### 4. 过滤

`job_monitor.py filter raw_jobs.json --tracker <跟踪表.xlsx> --data-dir <数据目录>`

输出即「今日待投清单」。数据目录建议与跟踪表同目录，保持同一台机器上历史记录连续（seen_jobs.json 负责「见过不重推」）。

### 5. 呈现与确认

把待投清单按编号列给用户（公司/岗位/薪资/链接），**等用户确认后再进入投递辅助**。用户可能要求剔除某些条目（用 `seen --url` 标记剔除）。

## 三、辅助投递流程（逐个岗位）

对用户确认的每个岗位：

1. 用浏览器打开岗位详情页 `url`。
2. 快速核对岗位信息与清单一致（防过期岗位）。
3. 找到「立即沟通」（Boss）或「申请职位」（智联）按钮，**停在点击前**。
4. 预填打招呼语：Boss 的沟通窗有输入框时，依据 `followup-templates.md` 场景1的首次沟通变体填入（自报家门 + 一句匹配点 + 表达意向，2-3 行内）；智联网申通常直接投递简历，无需招呼语。
5. **请用户检查并点击发送**——这一步永远不代点。
6. 用户确认发送后：`tracker_manager.py add` 写入跟踪表（渠道=zhipin/zhilian，备注=岗位链接），再 `job_monitor.py seen --url <链接>` 标记已处理。

## 四、风控红线（必须遵守）

- **频率**：页面间随机等待 5-15 秒；单日浏览岗位页 ≤ 50 个、进入沟通流程 ≤ 30 个。
- **节奏**：连续操作 15-20 分钟后建议暂停；不要整点、整分机械式触发。
- **验证码/滑块**：一旦出现，立即停止所有自动化操作，请用户人工完成验证；绝不尝试模拟或绕过。
- **异常信号**：页面出现「账号异常」「操作频繁」提示时，当天终止，建议用户 24-48 小时内只手动操作。
- **登录**：只用用户自己已登录的浏览器会话；不要脚本化输账密、不要尝试自动登录。
- **改版适配**：平台 DOM 改版导致解析失败时，重新人工查看页面结构再更新选择器，不要盲试大量选择器（会放大请求特征）。

## 五、每日定时监控（可选）

用户需要每日自动推送时，建议创建 automation：每天上午 10 点执行「抓取 → filter → 呈现清单」（只到第 5 步），用户白天碎片时间确认投递。automation 提示词中需写明跟踪表路径与数据目录。
