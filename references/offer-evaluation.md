# Offer 评估方法论

## 第一步：一票否决项筛查（先于打分）

对每个 Offer 先确认是否触碰一票否决项，触任一项直接淘汰、不进入加权打分。常见否决项（用户可自定义补充）：

- 单休或常态化大小周且无调休
- 试用期不缴 / 按最低基数缴纳社保公积金
- 公司现金流紧张、业务线近期裁员传闻
- 单程通勤超过 2 小时且无远程政策
- 岗位职责与 JD 明显不符（挂羊头卖狗肉）

## 三大维度与打分标准

每项 1-5 分。录入「Offer对比」工作表，脚本自动归一化计算。

### 薪资包（默认权重 40%）

脚本按年薪（含折算）相对最高者归一化为 0-5 分：年薪来源优先级为「年薪(万)」列 → 「月薪 × (12 + 年终奖月数)」折算。

人工复核要点（打分前确认，避免被数字迷惑）：
- base 与浮动绩效的比例：浮动占比高则实际到手打折
- 股票期权：行权价、归属周期、公司是否上市/可流动性
- 五险一金缴纳基数：按全额还是最低基数，差额折算进年薪
- 年终奖写进 Offer 还是口头承诺

### 发展前景（默认权重 30%）

- **技术匹配 (1-5)**：5 = 完全对口且有深度空间；3 = 部分匹配需补课；1 = 几乎无关。
- **成长空间 (1-5)**：5 = 有明确晋升通道与导师；3 = 靠机遇；1 = 天花板肉眼可见。

### 工作生活平衡（默认权重 30%）

- **稳定性 (1-5)**：5 = 盈利稳定的核心部门；3 = 普通业务线；1 = 边缘业务/有裁员传闻。
- **工作轻松度 (1-5)**：5 = 基本不加班；3 = 大小周/项目期加班；1 = 常态化 996。
- **通勤便利 (1-5)**：单程 <30 分钟 = 5；30-60 分钟 = 4-3；60-90 分钟 = 2；>90 分钟 = 1。

## 对比流程

1. 用 `add-offer` 将各 Offer 的薪资与评分录入「Offer对比」表；缺信息时逐项询问用户，不要编造。
2. 运行 `compare` 得到加权排序（默认权重：薪资包 40% / 发展前景 30% / 工作生活平衡 30%）。
3. 用户表达明显偏好时调整权重重跑，例如极度看重平衡用 `--weights 0.2,0.3,0.5`。

## 结果解读规则

| 分差（第一名 - 第二名） | 解读 |
|------|------|
| < 0.3 | 视为打平：用用户最在意的单一因素做最终裁决 |
| 0.3 - 0.8 | 倾向第一名：先复核低分者是否有可提升空间（如谈薪）再定 |
| > 0.8 | 明确倾向第一名 |

## 输出结论要求

- 必须列出每个 Offer 的「最强项」与「最弱项」（compare 已输出），让用户看到取舍，而不是只报分数。
- 薪资分接近满分的对比中，提醒用户关注 base 构成差异（脚本按总包归一化，不区分稳定性）。
- 给出建议但把最终决定权交给用户，避免"帮你做主"式结论。

## 谈判提示（对比后常见动作）

- 先拿到全部意向再谈判；用竞争性 Offer 争取 base 提升，而不只是签字费。
- 数字写在 Offer 上才算数；口头承诺要求补充进 Offer 或邮件确认。
- 谈薪成功后用 `update`/直接编辑更新表格数据，重跑 `compare` 再做最终决策。
